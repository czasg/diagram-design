# 结构图 · 盒子树

> 何时用：素材讲**系统由什么组成**，没有先后顺序（或只有局部流水线）。
> 数据：`../assets/template-structure.data.js`（只改 DIAGRAM/LINKS）→ `node scripts/build-structure.mjs <data.js> --check` 出 HTML 并自检
> **先做 SKILL.md Step 1 的内容建模**，本文件只讲怎么把建模结果翻译成数据。引擎在 `assets/engine-structure.js`，勿读勿改。

## 核心思想

整张图 = **一棵嵌套的盒子树**。模板里没有"层""侧栏""域"这些固定概念，它们都只是同一种盒子的不同摆法。
**骨架从建模来，不从示例来。**

| 建模出的关系 | 数据写法 |
|---|---|
| 上下支撑（分层） | root `dir:'col'`，每块一个横排容器 + `tag` |
| 并列 | 横排容器，子项默认**等宽**；超 5 → `wrap:N`（见「条目数与竖版」） |
| 流水线 | 横排容器 + `flow:true` → 相邻子项之间自动画箭头；过长 → `wrap:N` 蛇形折行（见下节） |
| 分组 | 子容器 + `title` |
| 侧挂治理 | 与主体同一横排，`tint:true` + 较小的 `grow` |
| 包含（部署：区 → 集群 → 节点） | 多级嵌套 |
| 网格 / 换行 | `wrap: 列数`——何时必用、怎么凑数见「条目数与竖版」 |

## 条目数与竖版（先凑数，再落数据）

模板的等宽行、`wrap` 列数、flow 折行都偏爱**整齐的条目数**。建模时把条目数当设计变量，不要画完再硬折：

1. **每组条目数取偶数、或目标列数的整数倍**——一行 4、`wrap:3`→6、`wrap:2`→4/6/8。奇数落单/半行空档（如 5 步 flow 的 3+2）是条目数没凑好，不是引擎问题
2. **流水线步数配合 `flow`**：4 步可一行直线箭头（最好读）；5 步只能蛇形且回折侧留空 → **能合并就并成 4**（语义上相邻的两步并一步，如「回边判断」并进「工具执行」），拆不开再 `wrap:N` 蛇形（见下节）
3. **分组禁止并排相乘**：带 `title` 的子分组 ≥2 → 一律 `dir:'col'` 上下堆叠；并排只留给 ≤2 个小组，且先估「组宽 × 组数」
4. **最宽行压在 ~4 卡内**（常见画布宽 ~1100、近方或微竖即可）；≥5 卡一行或宽高比 >1.5 就是横幅 → 回 Step 1 改条目数或改堆叠，别等 `tooWide` 拦

竖版是手段不是目的：同样信息，把「并排」换成「堆叠 + 整齐条目」，画布自然收窄；不必强求 960 窄条，行填满比绝对竖更关键。

## 字段

**容器**（有 `children` 就是容器）

| 字段 | 作用 | 默认 |
|---|---|---|
| `children` | 子节点数组，可无限嵌套 | 必填 |
| `dir` | `'row'` 横排 / `'col'` 竖排 | `'row'` |
| `flow` | 流水线：相邻子项之间画箭头（容器颜色） | false |
| `wrap` | 数字 = 网格列数（`wrap:3`、`wrap:4`）。何时必填、条目数怎么凑 → 「条目数与竖版」；flow 蛇形折行 → 下节。网格末行不足 N 列时子项自动拉伸铺满，不留右侧空洞 | 无 |
| `tag` | `['名', '副']` 左侧独立标签块，随容器高度拉伸；名字里的空格处断行 | 无 |
| `title` | 容器左上角标题 | 无 |
| `color` | 身份色，向下继承给图标、标题、标签、箭头 | 继承父级 |
| `grow` | 横排中分配宽度的权重；兄弟中只要有一个写了 grow，就全部按权重分 | — |
| `fit` | 横排子项按内容宽度分配（默认等宽）。仅在条目长短悬殊、等宽放不下时用 | false |
| `flat` | 子叶子不画卡片框，只显示图标 + 文字（深度 A） | 继承父级 |
| `bare` | 透明分组：不画底色、不加内边距，只用于排版 | false |
| `tint` | 底色改为身份色的浅底（侧挂体系） | false |
| `dashed` | 虚线边 | 第 3 级起自动虚线 |

**叶子**：`{ t:'标题', d:['一行说明'], icon:'database', id:'可选' }`
- `icon`：Lucide 图标名（见文末清单）；`false` = 不显示；不写 = 几何块（不推荐与图标混用）

**关系线** `LINKS = [[起点id, 终点id, '标签', 是否虚线]]`
- 只画堆叠和包含表达不了的关系，≤ 8 条

## 长流水线：`flow` + `wrap` 蛇形折行

步骤多（>5）或单行估宽会把画布拉爆时，给 flow 容器加 `wrap:N`。**children 仍按语义顺序平铺**，不要自己反序；渲染自动做蛇形（boustrophedon）：

```
1 → 2 → 3 → 4          children: [1,2,3,4,5,6,7]
              ↓         偶数行左→右占列 0,1,2…
7 ← 6 ← 5              奇数行从右往左占列 wrap-1,wrap-2…（转向侧对齐）
```

- **固定列宽按 `wrap:N` 算**（不按行内个数）：各行列对列，行末卡与下行首卡**中心必重合 → 回折永远是纯竖线**
- 末行不足 N 列时**不拉伸**，空列留在转向远端（奇数行留在左侧），转向侧仍占满
- 例：7 步 `wrap:4` → 上 4 列满、下 3 列靠右占 1–3 列，左侧空 1 列；④ 与 ⑤ 同在最右列，竖线直下
- 行内箭头随实际左右方向画（第二行箭头朝左）
- 列距用 `FLOW_GAP`（给箭头），行距自动加大给竖向连接
- **完整 DATA 示例**：`../assets/examples/flow-wrap.js`；模板内置完整成品示例（8 步 `flow+wrap:4`）也是这个写法
- 不要拆成两个独立 `flow` 容器来「假装」折行——那会丢掉跨行的先后关系

**整图** `DIAGRAM.lint = false` 可以关闭一致性检查。只在确实需要混合深度时使用，并在建模注释里写明理由。

## 自动规则

- **宽度**：横排默认等宽，各层左右边线对齐。只有最长的条目放不下时，才自动按内容宽度分配。
- **画布由最宽一行决定**：常见撑宽源是长 `flow`——对策见「条目数与竖版」与下节蛇形（不要硬塞一行拉成横幅，其他层会被等宽拉出大片空白）。
- **高度**：同一横排里的子项拉到同样高度；多出来的高度会分给叶子卡片，卡片内容垂直居中，**不会在底部留空**。
- **明度阶梯**：第 1 级 `#F2F4F8`，第 2 级 `#F9FAFC`，第 3 级白底加虚线；叶子卡片是白底加 1px `#E2E8F2` 边框。
- **lint**（check.js 读取，出现即判为不通过）：
  - 全图同时存在 flat 条目和卡片
  - 同一容器里有的卡片带说明、有的不带
  - 顶层块有的带 tag、有的不带
  - 图标名不存在
  - `sparseCards`：宽卡里文字只占左侧很小比例（最宽行撑开画布后等宽铺满）

## 坑（Wrong / Right）

1. **照抄示例骨架**
   - Wrong：不管内容是什么，都摆成“左侧层名 + 每层一排 + 中间主区/侧栏”。
   - Right：先按关系类型建模。本来是流水线的就用 `flow`，本来是并列的就别硬拆成两层。

2. **信息深度不统一**
   - Wrong：用户层、接入层只有 3 个短词，存储层却是带说明的卡片，看起来像拼起来的。
   - Right：全图选同一种深度；单薄的块补上职责、协议或用途。lint 会拦截这种情况。

3. **太薄的块独占一层**
   - Wrong：“用户”一层只有 3 个短词，一大半是空白，顶部显得稀疏。
   - Right：合并成一层“使用方”，里面分“用户 / 接入渠道”两组。

4. **流水线画成并列格子**
   - Wrong：查询改写、混合检索、重排序……画成等宽格子，看不出先后顺序。
   - Right：用 `flow:true` 画出箭头。这往往是整张图最有信息量的部分。

5. **为了“不像表格”故意让宽度不一**
   - Wrong：卡片宽度忽大忽小，各层边线全部对不上，看起来乱。
   - Right：默认等宽对齐；层次感靠关系形态（流水线、分组、侧挂）和明度阶梯来体现。

6. **层间画箭头**：堆叠本身就表达了依赖关系，不要再画箭头。

7. **侧挂体系用对比色**：用 `tint:true`，保持同一色系、低饱和。

8. **图标一半有一半没有**：要么每个条目都配图标，要么整张图都不用。

9. **关系线穿过卡片**：check.js 报 `linkHits` 时，调整 children 的顺序，让关系线两端的卡片相邻。

10. **一层横排堆太多（含长流水线）**
    - Wrong：数据层 7 个卡片挤成一行；或 8 步 `flow` 硬塞一行，整图被拉成横幅，其他层被等宽拉出大片空白。
    - Right：超 5 → `wrap:N`（非流水线网格、长 flow 蛇形同理）；规则见「条目数与竖版」与蛇形节。自检 `lint` / `tooWide` / `sparseCards` 会拦。

11. **并排子分组把宽度相乘**（横幅头号来源）
    - Wrong：一层里 3 个带 `title` 的子分组横排 → 整层 = 组宽 × 组数，几层就能把画布拉成横幅（如 1680×900），其余层被等宽拉出大片空白。
    - Right：分组 ≥2 且组内还有卡片 → **一律上下堆叠**（`dir:'col'`）；并排只留给 ≤2 个小组，先估「组宽 × 组数」（「条目数与竖版」第 3 条）。

12. **条目数不配合模板，画完再硬折**（空洞/落单来源）
    - Wrong：流水线按语义拆成 5 步 → 只能 `wrap:3` 蛇形 3+2，回折侧空一列；或一组 5 项硬塞一行。内容没动，布局留疤。
    - Right：建模时先凑数（偶数 / 列数整数倍、能并则并）——细则全在「条目数与竖版」，**条目数是设计变量**，别画完再折。
