# 泳道时序图

> 何时用：素材有**先后顺序**——谁调用谁、谁返回、第几步，且**消息传递是主角**。
> 与流程图（flowchart.md）的边界与词汇差异：见 SKILL.md Step 2。
> 数据：`../assets/template-flow.data.js`（只写 TITLE/LANES/STAGES 等）→ `node scripts/build-diagram.mjs flow <data.js> --check` 出 HTML 并自检。引擎 `engine-flow.js` 勿读勿改。

## 结构

```
[左侧阶段编号区 ~200px] [N 条泳道，均分；泳道间距 ≥150，宽度随泳道数自动加宽]
```

自上而下按阶段分区，每个阶段是一条**横跨全幅的浅色带**。

## 数据格式

```js
const TITLE = '…', SUBTITLE = '一句话主线';
const LANES  = [ {t:'用户'}, {t:'智能体'}, … ];      // 颜色按顺序自动取六色
const STAGES = [
  { no:'01', name:'阶段名', msgs:[                    // color/bg 省略 = 按顺序取阶段四色
    [起点泳道, 终点泳道, '标签', '注释', 是否回流, 是否自处理],
  ]},
];
```

- 泳道 3–7 条；每阶段 2–6 步；阶段 2–5 个
- `f===t` 且第 6 位为 `1` → 自处理括号；右侧放不下时**标签和注释整体翻到左侧**
- 回流（第 5 位 `1`）→ 虚线、透明度 0.8

## 可选：片段 / 注释 / 异步（按需使用，默认不用）

**默认画法就是线性步骤 + 回流虚线**，绝大多数“讲清一次请求怎么走”的图不需要下面这些。
只有素材里**真的存在**以下情况才加：

| 语法 | 何时用 | 写法 |
|---|---|---|
| `alt` 分支 | 走哪条路会**改变后续步骤**（缓存命中 / 未命中、鉴权通过 / 拒绝） | `{ frag:'alt', label:'条件', branches:[{guard:'命中', msgs:[…]}, {guard:'未命中', msgs:[…]}] }` |
| `loop` 循环 | 重试、轮询、分页拉取，且**重试本身是要点** | `{ frag:'loop', label:'最多 3 次 · 超时重试', msgs:[…] }` |
| `par` 并行 | 几路调用同时发出，**并行是性能要点** | `{ frag:'par', label:'双路召回', branches:[…] }` |
| `opt` 可选 | 某段只在特定条件下发生，且读者需要知道 | `{ frag:'opt', label:'cite=true', msgs:[…] }` |
| 注释 | 一句话说明协议约定 / 关键约束，消息标签放不下 | `{ note:'说明', over:[起泳道, 止泳道] }` |
| 异步 | 发出后**不等待**（写日志、发事件、投递 MQ） | 消息第 5 位写 `'async'` → 实线 + 开口箭头，图例自动补一项 |

片段可以嵌套（`branches` / `msgs` 里再放片段），但要克制。

**克制规则**（超了模板写 lint，check.js 判不过）：
- 片段 ≤ 3 个、嵌套 ≤ 2 层、注释 ≤ 3 条
- 能写进消息注释（第 4 位）的，就不要加框。例如“失败时重试”只是附带说明，就写在注释里；重试是这张图要讲的重点，才用 `loop`
- 一个分支里只有一条消息、并且不影响后续步骤 → 写进注释，不加 `alt`
- 片段一多，说明一张图讲了好几件事 → 拆成“主流程图 + 异常 / 重试图”两张

完整例子：`../assets/examples/flow-fragments.js`（1 个 alt + 1 个 loop + 1 条注释 + 1 条异步）。

飞书画板：片段框转成矩形加文字，开口箭头转成 `line_arrow`，节点通道和 SVG 通道都可用。

## 参数（模板已内置）

| 元素 | 值 |
|---|---|
| 字号 | 26 标题 / 阶段大号编号（28% 透明）· 12.5 正文 / 胶囊 / 阶段名 / 圆点序号 · 10 注释 |
| 分区带 | 横跨全幅，圆角 12，段间 10，底 = 阶段浅色；左缘 4px 阶段色竖条 |
| 顶部胶囊 | 高 40，宽 ≥112（随文字加宽），1.5px 同色系描边 |
| 消息圆点 | r=16 + 白圈 r=19 |
| 消息行距 | 62 |
| 流程箭头 | 1.8px，阶段色 |
| 泳道竖线 | 2.2px `#A9B5C4` `6 6` |
| 标签垫片 | 阶段底色，不用白色 |

### 阶段色（深色供线/点/阶段名，浅色供带底）

| 色 | 深 | 浅 |
|---|---|---|
| 蓝 | `#3E63DD` | `#F5F8FE` |
| 琥珀 | `#8A6A12` | `#FCF8EF` |
| 绿 | `#1B7D57` | `#F2F9F5` |
| 紫 | `#7B4A9E` | `#F9F5FC` |

超过 4 阶段循环使用，不加新色相（超过 5 阶段建议拆图）。

### 三套颜色各管一件事

| 元素 | 回答什么 | 颜色 |
|---|---|---|
| 顶部胶囊 | 这是**谁** | 六色各一 |
| 分区带 | 这是**第几步** | 阶段浅底 |
| 箭头 + 圆点 | 属于**哪个阶段** | 阶段深色 |
| 正文 | 信息本身 | `#2C3441` |

## 坑（Wrong / Right）

1. **圆点太小**：r=7 / 11 看不出"这是一步" → r=16
2. **泳道虚线太细**：1px 碎成点 → 2.2px 粗而浅
3. **胶囊全灰求"语义唯一"**：整图死掉 → 胶囊六色 + 阶段色并存
4. **颜色只上容器**：分区带彩色、箭头灰色 → 箭头、圆点全用阶段色
5. **左侧只有名称**：下方大片空 → 大号透明编号 + 名称，整块垂直居中
6. **跨泳道标签压线**：模板 `pickX` 候选打分已处理；手画时用 `layout_lib.mjs` 的 `pick_label_x`
7. **底部再画一排参与者**：冗余 → 只画顶部，泳道线收在最后消息下 24px
8. **把结构塞进泳道**：某泳道里罗列一堆组件 → 那是结构，回结构图另画一张
