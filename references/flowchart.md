# 流程图 · 主干直行

> 何时用：素材是**一件事怎么一步步做完、遇到判断走哪条路**——业务流程、审批/规则、异常与重试。
> 模板：`../assets/template-flowchart.html`（只改 DATA 段）
>
> **与泳道时序图（flow.md）的边界**：拿掉所有参与者名字图还成立 → 流程图；"谁传给谁"就是全部信息 → 泳道时序。
> 两者词汇绝不混用：流程图里没有消息标签/调用返回；泳道图里没有菱形出口条件。模糊地带判定见 SKILL.md Step 2。

## 设计核心（按重要性，出图前逐条过）

1. **主干是一条直线**。判断条件朝主路径设计：主路径走"是"出口直下主干，例外走"否"侧出；靠翻转条件实现（≤↔＞、通过↔驳回）。三条细则：
   - **主干 = 读者最该关注的那条路**（这张图的叙事主线），不是随便挑条顺的。主题是"怎么审批"，主干就是审批链；主题是"日常怎么流转"，主干就是高频路径
   - 翻转后若变成双重否定（"是否无需审批？"）**别硬翻**——改让"否"出口直下，"是"侧出
   - 从开始到完成全用"是"贯通，读者顺着一条线读完主流程，不用左右找路
2. **出口标签补语义**。写"是：大额 / 否：小额"，不写裸"是/否"——语义由标签承担，不让读者在脑内翻条件。分隔用**全角冒号**，别用中点 `·`（10px 边标签下几乎看不见）。汇回边有约定也标（"重提≤3次"）
3. **责任带是背景，不参与排版**（可选，看不清谁负责才加 `LANES`）。竖直 = 流程推进，换带 = 责任移交，横向只留给分支；主干换带不换列，箭头穿过别人的带没关系
4. **连线就近接口**：竖线进顶/底边、横线进侧边；汇回优先接目标节点的接口（自动通过→打款 的左边），不中途插干线、不绕远兜圈；进出同一节点的线走不同侧
5. **布局居中**：主干在带区水平中心，左右分支区宽度对称；分支节点在自己的责任带内左右均衡，避免一侧挤一侧空
6. **间距**：相邻节点边到边 ≥44px（模板 GAP=46），箭头两端不贴节点；同排横向 ≥20px

## 数据格式

```js
const TITLE = '…', SUBTITLE = '一句话主线';
const LANES = [{t:'员工'}, …];        // 可选：责任带，2–7 条；省略 = 无带（lane 字段随之忽略）

const TRUNK = [                       // 主干：自上而下一条直线
  { id:'s',  t:'开始',        shape:'start', lane:0 },
  { id:'a',  t:'提交报销单',  lane:0 },                  // shape 缺省 = action 卡片
  { id:'d1', t:'金额 > 1000？', shape:'decision', lane:1, yes:'是：大额' },
  …
  { id:'e',  t:'完成',        shape:'end', lane:3 },
];

const BRANCHES = [                    // 侧支：挂主干判断的左/右出口，汇回主干节点
  { from:'d1', side:'l', label:'否：小额', style:'quick',
    nodes:[{ id:'q1', t:'自动通过', lane:1 }], to:'c', toSide:'l' },
  { from:'d2', side:'r', label:'否：驳回', style:'err', back:true, toLabel:'重提≤3次',
    nodes:[{ id:'x1', t:'退回修改', lane:0 }], to:'a', toSide:'r' },
];
```

| 字段 | 说明 |
|---|---|
| `shape` | `'action'`（缺省·卡片）/ `'decision'`（菱形）/ `'start'` / `'end'`（胶囊） |
| `yes` | 判断直下出口标签，**必填且补语义**（`是：通过`；裸 `'是'` 或缺省 lint 拦） |
| `side` | 侧支挂哪边 `'l'`/`'r'`，缺省 quick→左、err→右（快捷靠左、异常靠右） |
| `style` | `'quick'`（琥珀，快捷/普通分支）/ `'err'`（红，异常/驳回） |
| `label` | 分支出口标签，**必填**（lint 拦裸缺） |
| `to` / `toSide` | 汇回的主干节点 id / 接口侧 `'l'|'r'`（缺省按左右方向就近） |
| `back:true` | 汇回边画虚线（回边/重试），配 `toLabel` 标约定 |
| `lane` | 责任带下标；只有 `LANES` 存在时才校验 |

布局规则（模板自动，不用管）：侧支链同排平进目标侧边；目标在上方就近接**底边**、在下方就近接**左/右侧边**；主干判断在左/右顶点出线。

## 参数（模板已内置）

| 元素 | 值 |
|---|---|
| 字号 | 26 标题 / 12.5 节点正文·带名 / 10 副标题·边标签·图例 |
| 卡片 | 白底 + 1px `#D8DEE7` 边，圆角 8，高 44，宽 = 文字 + 48（≥120） |
| 菱形 | 白底 + 1.5px 路径色描边，高 84，宽 ≥150 |
| 起止胶囊 | 高 36，圆角 = 高/2，底 `#E8F5EE` / 边字 `#1B7D57` |
| 线 | 1.8px，圆角接头；进 `end` 的线用绿色 |
| 边标签 | 10 号，白底垫片（圆角 3），主干 yes 放线右侧，其余放最长水平段上方 |
| 责任带 | 圆角 12，内容 ±26 推导、重叠从中间分；带名纯文字右对齐贴带左缘，**不用胶囊按钮** |
| 间距 | 节点间 GAP 46 / 侧支走廊 64 / 同排 ≥20 |

### 线条颜色 = 路径类型（一个维度一套色）

| 色 | 值 | 用途 |
|---|---|---|
| 蓝 | `#3E63DD` | 主干（是：直下） |
| 琥珀 | `#8A6A12` | 快捷分支 / 汇回 |
| 红 | `#B4232A` | 异常分支 / 回边（虚线 `7 6`） |
| 绿 | `#1B7D57` | 起止胶囊 / 进入终点 |

责任 = 带底浅色 + 带名色（琥珀/蓝/紫/绿四色循环），**不上节点**。节点保持普通白卡。

## 可选 / 克制

- `LANES` 省略 = 纯流程图（主干 + 侧支），默认推荐；"每步谁负责"是读者需求时才加
- 判断 ≤5 个、侧支 ≤4 条、节点 ≤15 个（红线，lint 拦）；超了**拆主图 + 子流程卡**：把一段侧支收成一张卡片，另出一张子图
- 分支里再长出子分支 → 先想能不能拆图；确要保留，`nodes:` 里多排几个节点即可（链自上而下串联）

## 自检（模板写 lint，check.js 拦）

缺 start/end 胶囊 · 判断没有侧支出口 · **出口缺语义标签**（分支 `label` 必填 / 判断 `yes` 裸「是」）· 判断被塞进侧支（判断必须上主干）·
分支 id 不存在 / 起点不是判断 / style 拼错 · 节点 >15 / 判断 >5 / 侧支 >4 · 责任带 2–7 条 ·
lane 越界 · 节点重叠或过近（间距红线 44）。

## 坑（Wrong / Right）

1. **条件顺着口语写**：「金额 ≤ 1000？」→ 是 = 直通捷径占了主干，审批主线被挤到侧边 → 条件朝主路径设计：「金额 > 1000？」→ 是 = 审批直下
2. **裸"是/否"标签**：读者要脑内翻条件 → 补语义："是：大额 / 否：小额"
3. **蛇形主干**：按责任带的行摆节点，主干拐成阶梯 → 节点纵向位置只由流程顺序决定，带只是背景，换带不换列
4. **节点加左缘色条、带名画成胶囊按钮**：装饰抢戏 → 普通白卡 + 纯文字带名，颜色只上线条与带
5. **间距 20px 挤成一团**：尤其起止贴着相邻卡片 → 边到边 ≥44，起止胶囊同样待遇
6. **连线绕远接侧边**：驳回线绕最外圈接"退回修改"右边 → 就近接口：从上方来就接**底边**
7. **汇回中途插干线**：接一根横线戳进主干中间 → 接目标节点的接口（打款 的**左边**）
8. **一边挤一边空**：分支全堆右侧，左边大片留白 → 主干居中、左右分支区对称
9. **回边穿卡片 / 挤在两卡缝里**：走最外圈走廊，短线段上放短标签（"重提≤3次"），别写长句
10. **为了直线硬翻条件**：翻成双重否定更难懂 → 别硬翻，让"否"直下、"是"侧出，标签写清楚

完整例子：`../assets/template-flowchart.html` 自带的"报销审批流程"就是按以上全部规则做的范例（数据在 DATA 段，顶部注释即字段文档）。
